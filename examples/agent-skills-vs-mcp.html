Decision under pressure

Should an AI capability be an Agent Skill, an MCP server, or both?

Default to a Skill for reusable procedure and bundled context. Add MCP for live or dynamic tools and resources; combine them when the Skill should orchestrate an MCP-backed capability.

Reasoning edges

  1. The package format directly represents reusable procedure and on-demand supporting material.

  2. A documented open format has a credible portability path beyond one chat session.

  3. Portable authoring is further along than stable remote discovery and distribution.

  4. MCP's primitives and transports are designed for live capability exchange.

  5. A Skill can describe when and how to use tools that an MCP server exposes.

  6. A live remote integration adds authorization and operational risk, so MCP should not be the default for static guidance.

  7. Choosing a Skill changes the packaging boundary; it does not remove the need to review code and permissions.

  8. Reusable procedure and bundled context fit the Skill boundary.

  9. Live data and actions fit a protocol boundary.

  10. The formats compose when a workflow needs both procedural knowledge and runtime capability.

  11. A shared behavioral suite is needed before claiming equivalent portability in practice.
