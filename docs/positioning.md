# Positioning

## Category

Doubt is an **epistemic behavior layer for AI agents**.

It is intentionally smaller than an agent framework and broader than a coding-only guard. The
product wedge is anti-sycophancy; the long-term category is inspectable judgment skills.

## One-line pitch

Your AI is too agreeable. Give it healthy doubt.

## The enemy

Confidently polished answers built on an untested premise.

## Audience

1. Developers using coding agents for consequential work.
2. Technical leaders reviewing AI-authored plans and completion claims.
3. Researchers and analysts who need current claims separated from inference.
4. Teams standardizing agent behavior across providers.

## Differentiation

| Alternative | What it does | Why Doubt is different |
| --- | --- | --- |
| Fact-checking agent | Re-researches a finished answer | Changes the reasoning posture before the answer is finalized |
| Prompt/security scanner | Finds dangerous text or configuration | Finds agreement, certainty, and evidence failure modes |
| Agent framework | Owns execution and model routing | Drops into the agent the user already has |
| Generic “be critical” prompt | Adds vague caution | Uses a short protocol, evidence ladder, and completion-proof rules |
| AI detector | Guesses whether text came from a model | Reviews claims without guessing authorship |

## Brand rules

- Voice: direct, calm, slightly provocative.
- Avoid: doom, “truth machine,” fake scientific precision, hostility toward users.
- Primary line: “Your AI is too agreeable.”
- Secondary line: “Find the load-bearing claim. Try to break it. Then keep moving.”
- Visuals: near-black, violet, cyan, mint; terminal typography; evidence over decoration.

## Honest product boundary

Doubt cannot guarantee truth or override a model's higher-priority instructions. The linter detects
language patterns, not ground truth. This boundary is part of the pitch: inspectable discipline
instead of magical claims.
